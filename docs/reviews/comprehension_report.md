### What this proposes

* **`FeatureRange` (lines 1..313):** Varal is a native macOS menu-bar utility (`LSUIElement = true`) that renders an interactive catenary clothesline on a single user-selected display at the window level between the desktop wallpaper and Finder desktop icons (`CGWindowLevelForKey(.desktopIconWindow) - 1`). It switches automatically between a single horizontal rope in landscape orientation and vertically stacked parallel ropes in portrait orientation, hanging two built-in first-party companion cards (`Atmos` for live weather telemetry via an embedded `WKWebView` bridge and `Get Long Weekend` for discovery/multi-block vacation countdowns via `varal://weekend` deep links) alongside immutable daily task paper slips. Users complete tasks by dragging a slip downward past `48pt` to tear it off into a bottom-right laundry basket (`cesto`)—causing the rope to recoil upward—while unfinished slips stay on the line past the `04:00 AM` rollover with weathered edges, and a governor pauses the 60fps physics simulation whenever the line is occluded (`>85%`), in fullscreen, in Low Power Mode, under macOS Reduce Motion, or manually paused.
* **`DetailedRange` (lines 314..389):** The detailed implementation plan defines 26 deliverables across two phases: three workspace root specification and grayscale prototype artifacts (`concepts_brief.md`, `wireframe_spec.md`, and `wireframe.html`) and a Swift 6 / macOS 14+ native package (`Varal.app` and `VaralTests`). It breaks the native target into protocols and registries (`CompanionPiece`, `CompanionPieceRegistry`), immutable data models and JSON-backed stores (`TaskSlipStore`, `HolidayPlanStore`, `RolloverScheduler`, `URLSchemeRouter`), first-party companion piece views (`AtmosPiece`, `GetLongWeekendPiece`), the catenary physics engine and occlusion governor (`ClotheslinePhysicsEngine`, `OcclusionGovernor`), AppKit window/canvas views (`DesktopYardWindow`, `ClotheslineCanvasView`, `TaskSlipView`, `LaundryBasketView`, `MenuBarController`), and three unit test suites verifying deep-link idempotency, rollover weathering, and physics/governor rules.

### How the existing system works, per this document

* **`FeatureRange` (lines 1..313):** Currently, macOS users must choose between intrusive productivity apps (which rely on floating windows, badges, streak counters, and notification banners) and rigid macOS Sonoma/Sequoia desktop widgets (which sit on a static grid with no shared physics or tactile completion mechanics). Meanwhile, the author's existing companion web apps—**Atmos** (`atmos.reggiespace.ca`) for live local weather and **Get Long Weekend** (`getlongweekend.ca`) for holiday bridge-day planning—exist only inside browser tabs that vanish when closed, with no native desktop presence unifying daily commitments, local weather, and vacation countdowns at wallpaper level.
* **`DetailedRange` (lines 314..389):** Varal is a greenfield native macOS application and wireframe package being created from scratch (`Package.swift`, `Varal/`, `VaralTests/`, and the three companion specification/wireframe files). It integrates with the existing external web applications `atmos.reggiespace.ca` (hosted in compact piece mode inside `AtmosPiece`'s `WKWebView` and posting `EnvironmentSnapshot` payloads over `WKScriptMessageHandler`) and `getlongweekend.ca` (which triggers `varal://weekend?start=...&end=...&plan=...` deep links handled by `URLSchemeRouter`), while keeping web repository changes outside this repo's deliverables.
